# HyperOS-Fcm-Hook

在 HyperOS / MIUI 上让依赖 FCM 推送的海外应用（Telegram、WhatsApp 等）恢复**实时收消息**的 Xposed 模块。

## 它解决什么问题

国产 ROM 为了省电，在系统侧对后台应用加了几道限制。结果是 FCM 推送到达后：

- 应用被强停过 → **广播根本送不进去**
- 应用没有运行 → 被自启动拦截，**拉不起来**
- 应用刚被拉起 → 立刻又被省电机制冻结，**网络断开，拿不到消息内容**

表现就是「必须打开应用才收得到消息」，或者通知延迟很久才出现。

本模块在系统服务侧补上这几环，让推送链路完整走通。

## 界面能看到的功能项

v1.2.32 提供以下开关 / 状态展示（均为模块界面上可见的项）：

| 分类 | 功能项 |
| --- | --- |
| 广播唤醒 | 广播能拉起已停止应用、唤醒、强停判定 |
| 冻结豁免 | 不被冻结、内核解冻、秒临时豁免、解冻成功/失败计数 |
| GMS 保护 | 不被断网、不进智能限制、内部维持「不受限」、电源策略三闸门 |
| 状态与记录 | 目标应用状态查询、推送投递记录、实例区分（主实例 / 分身） |

> 具体实现方式不在本仓库范围内。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 系统 | HyperOS / MIUI，Android 16 实测通过 |
| Root 方案 | KernelSU 或 Magisk |
| 框架 | LSPosed |
| 作用域 | 必须勾选 **`android`**（system_server）+ **`com.miui.powerkeeper`** |

> 作用域两项缺一不可。只勾一项会出现「广播通了但 GMS 被限」或反之的半残状态。

## 安装

1. 到 [Releases](../../releases) 下载 APK 并安装
2. LSPosed 管理器里勾选本模块，**作用域勾上上面两项**
3. 重启手机（`ctl.restart zygote` 软重启即可加载 hook）
4. 打开模块界面确认各项已生效

> 若 `adb install` 被系统拦截，改用推送后本地安装：`adb push xxx.apk /data/local/tmp/ && pm install -r /data/local/tmp/xxx.apk`

## 已知限制

- **hook 层改动必须软重启生效**，改动后的首次推送会走完整冷启动流程，耗时明显偏长属正常现象
- 本模块针对特定 ROM 版本的方法签名编写，**换 ROM / 升级系统后可能失效**（失效时表现为 hook 不生效，不会导致崩溃）
- 修改系统服务行为有风险，请确保你知道如何救砖（备份、 Recovery 可用）
